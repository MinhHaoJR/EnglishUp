# EnglishUp implementation plan

## Assumptions

- Build a local-first single-user MVP in this empty repository using the requested stack.
- Original bundled learning content covers A2–B2; A1/C1 filters show an honest empty state.
- Speech availability depends on the browser; recording and self-assessment remain available independently of recognition.
- Offline rule-based writing feedback is the MVP; the optional LLM provider and stretch features are out of scope.

## Milestones

1. Scaffold React 18, strict TypeScript, Vite, Tailwind, routing, bilingual shell, Dexie and settings.
2. Vocabulary content, custom decks/CSV, four practice modes and SM-2 scheduling.
3. Reading passages, questions, evidence and dictionary/save flow.
4. Listening scripts, sentence playback, exercises and shared word alignment.
5. Speaking recording, recognition, read-aloud and topic-talk assessment.
6. Writing drafts, rule-based feedback, history and comparisons.
7. Dashboard, unified attempts, progress and validated data backup/restore.
8. Accessibility and error-state polish, smoke tests, content documentation and README.

## Verification

After every milestone run lint, typecheck, tests and production build, fix failures, then create a conventional commit when Git is available. Final checks include persistent attempts and export/reset/import round trip. Verify browser UI when a browser automation surface is available. Microphone/audio require a real device and permission; report any unverified hardware behavior honestly.

- Week 3 completed: 60-second quiz race. The API loads `vocabulary.json` and `vocabulary-it.json` (linked into its output, one content source with the client), draws 60 words per game with four Vietnamese meanings, keeps the answers server-side and grades each answer in order (`POST /api/game/start`, `/{id}/answer`, `/{id}/finish`, `GET /api/game/records`; `GameSessions`, migration `AddGame`). Answers after 60 s + 3 s grace get 409; `Answered` is a concurrency token so a double submit counts once; finishing twice returns the same result. Score = 10 × correct + 5 × best combo; points = score / 10 within the shared daily cap. Time comes from `TimeProvider` so tests move a manual clock. - Week 4 (recommendations) completed: the dashboard plan is no longer fixed. `src/services/recommend.ts` puts vocabulary first when reviewed cards are due, then ranks skills by need = (100 − average of the last 5 attempts) + 5 per day since last practice (capped at 14 days); untried skills come first. Each step shows its reason (due cards, untried, recent score below 70%, 3+ days unpractised, keep it up) and the hero button opens the top step. It runs in the browser on Dexie data, so it works offline and without an account; attempts from today are ignored so the plan stays fixed while the learner ticks it off. 127 client tests (5 new) and 56 server tests pass.
- Week 4 (AI provider) decided 2026-11-09: Google Gemini API, free tier, one key for both models (checked against ai.google.dev / aistudio.google.com docs that day). Answers: `gemini-3.6-flash` (stable); `gemini-3.5-flash-lite` if the free quota runs short. Embeddings: `gemini-embedding-2` at 768 dimensions (auto-normalised below 3072, fits a pgvector HNSW index; documents as `title: … | text: …`, questions as `task: question answering | query: …`, the model takes no `task_type`). Model names live in server configuration, the key in user-secrets as `Gemini:ApiKey`, never in the client. Free-tier limits: content may be used by Google and read by human reviewers, so only learning content and the learner's question are sent, never email, display name or history; users must be 18+ under the API terms (the thesis demo uses adult accounts); free-tier rate limits are shown only in AI Studio, so the assistant needs a server-side per-user limit and a friendly 429 message.
